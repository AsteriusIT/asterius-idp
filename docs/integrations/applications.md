# Native application OIDC recipes

Grafana 13.2.3 has [native acceptance evidence](evidence/grafana-2026-10-03.json): 14 checks cover real login, Viewer authorization, thirty second session expiry and native logout/replay refusal. Argo CD 3.5.3 has [native acceptance evidence](evidence/argocd-2026-10-03.json): 16 checks cover real S256 login, bounded observer RBAC and actual native logout/replay refusal. Harbor 2.15.2 has [native acceptance evidence](evidence/harbor-2026-10-03.json): 17 checks cover real S256 login, explicit private-project Guest authorization and native logout/replay refusal.

Each application requires an administrator to enable standard OIDC for its tenant and explicitly select that profile on one confidential client. Register authorization code, `client_secret_basic`, S256 PKCE, `openid email`, the exact HTTPS callback, and explicitly unbound access tokens only for native Bearer compatibility. Asterius defaults remain FAPI. PAR, public/CLI clients, refresh grants and downstream DPoP are outside these recipes. Bearer UserInfo belongs to this selected OIDC client; its tokens cannot authenticate SCIM or management APIs. All three fixtures register ES256 ID-token signing and the native products validate the issuer signature and client audience.

Use the existing [application setup guide](../integrating-a-confidential-client.md#register-through-the-console), save the exact callback and explicitly selected profile, then export **Saved configuration** and run **Run integration check** on that saved application. Keep the one-time generated client secret in the product secret manager. The disposable native fixtures bootstrap only their own test client; they do not provision or alter an operator’s deployment.

| --- | --- | --- | --- |
| Grafana 13.2.3 | `/login/generic_oauth` | Exact issuer `sub` plus verified email → Viewer; strict denial otherwise | [grafana.ini.in](../../integrations/applications/grafana.ini.in) |
| Argo CD 3.5.3 | `/auth/callback` | Exact issuer `sub` → observer of one configured project; no default role | [argocd-configmap.yaml.in](../../integrations/applications/argocd-configmap.yaml.in) |
| Harbor 2.15.2 | `/c/oidc/callback` | Stable issuer `sub` as native username; explicit local private-project Guest membership | [harbor-oidc.json.in](../../integrations/applications/harbor-oidc.json.in) |

Obtain the actual issuer subject from verified tokens. Local account UUIDs and email addresses are not substitutes for `sub`; do not make a role mapping from a caller header. The native fixtures preseed opaque subjects only in their owned test databases. No group scope, group release or administrator-group mapping is configured. Claims and memberships require a separately reviewed mapping before enabling group authority.

Grafana's generic OAuth ID-token signature validation defaults off in this version: the template explicitly enables it and pins the tenant JWKS URL. It also selects S256, header client authentication, the source CA and strict role assignment, and disables local Basic/anonymous login and Grafana administrator assignment. Store the client secret and application signing secret in private mounted files. For a private issuer CA, configure both `tls_client_ca` and the native process trust store (`SSL_CERT_FILE` in the runner): Grafana’s JWKS fetch uses process trust. Grafana normalizes the display login to lower case; the strict role expression compares the original verified subject, with insecure email lookup disabled. The native session bound is 30 seconds with no refresh; actual expiry returns 401. Source logout leaves that separate session alive until native expiry or logout. The tested authorization-code flow uses state and S256 without sending a nonce; nonce support is not advertised.

Argo CD's template enables PKCE, specifies the sole client audience and rejects missing audiences. Its source CA is embedded as public trust material. Put the client secret in a separately managed `asterius-oidc` Kubernetes Secret with the `app.kubernetes.io/part-of: argocd` label; the ConfigMap references it. Native administrator and anonymous access are disabled. Preserve independent baseline RBAC. The native logout handler is `/auth/logout`; legacy `/api/v1/session` DELETE is not a revocation operation and real access remains active. The native handler clears its cookie and revokes an identifiable captured token in Redis. Source logout remains separate. The real native handler returns 303; the cleared browser and captured-token replay both return 401. The tested code flow uses S256/state without nonce. The source ID-token lifetime is 300 seconds in this fixture; source logout alone still leaves native access alive. The disposable fixture creates its own kind cluster with explicit private kubeconfig and disables reconciliation, repository and notification controllers. It tests the real server OIDC/RBAC API against seeded resources, without deploying or fetching an application.

Harbor's template contains public settings only. Add its client secret from a private secret-manager file when submitting the authenticated configuration API request; do not save that value in this template or command arguments. Keep certificate verification enabled and install the source CA in Harbor's native trust directory. OIDC onboarding creates a stable native account without granting private-project access; an administrator must assign the exact native user Guest in a bounded project. Administrator-group mapping is empty. Local OIDC logout is selected: the native `/c/oidc/logout` returns 302 and both the next private read and captured-session replay return 401. Source logout alone leaves native access active. The tested authorization-code flow sends state and S256 without nonce; nonce support is not advertised. Native `sid` cookies are Secure, HttpOnly and SameSite Lax. The authenticated system-info API reports the runtime version; anonymous system info intentionally omits it. The fixture preserves Harbor’s separate local bootstrap administrator only for its own private configuration and Guest assignment. Registry publication, CLI secrets, scanners and complete registry/job-service health are outside this application login/RBAC recipe.

Native session cookies, cached ID/access tokens and product storage remain sensitive. Keep them out of logs and diagnostic exports; disable SSO debug logging. Serve each application over HTTPS with its own certificate and pin the issuer CA. The self-signed browser exception and shared source/application certificate in acceptance fixtures are confined to disposable tests; native backends still verify the source CA.

Run `scripts/grafana-acceptance.sh`, `scripts/argocd-acceptance.sh` or `scripts/harbor-acceptance.sh` with `ASTERIUS_BIN` pointing to a verified prebuilt server and `ASTERIUS_ACCEPTANCE_DB_CONTAINER` to a controlled PostgreSQL fixture on local port 5433. Install the locked browser dependencies with `npm ci --prefix e2e`, then Chromium with `cd e2e && npx playwright install chromium`. All runners require Docker, Python 3.11+, Node and OpenSSL; Argo CD additionally requires kind/kubectl, and Harbor requires Docker Compose, buildx and PyYAML. Each runner owns a nonce-named database, process and private temporary files. Argo CD creates a new nonce-named cluster and never selects or mutates the user's existing context. Harbor generates a unique compose project and container/network names, confines every mount to its private directory, and publishes only its loopback HTTPS port. Each runner removes only its own resources and emits sanitized evidence after cleanup. Execute them sequentially to bound disk usage.
