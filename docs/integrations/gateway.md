# OAuth2 Proxy gateway profile

This opt-in profile protects an application with OAuth2 Proxy 7.15.5 and Envoy 1.39.1. Asterius uses an explicitly enabled standard OIDC confidential client: authorization code, `client_secret_basic`, S256 PKCE, nonce validation, ES256 ID tokens, and verified email. Register the exact HTTPS `/oauth2/callback` redirect and `openid email` scopes. The default FAPI profile remains unchanged.

The supplied [OAuth2 Proxy configuration](../../integrations/gateway/oauth2-proxy.cfg.in) and [Envoy configuration](../../integrations/gateway/envoy.yaml.in) are the files used by the native acceptance runner. Replace the issuer, public gateway origin/authority, client ID and exact Envoy peer IP. Provide private client-secret and cookie-key files; the client secret has no trailing newline, and the cookie key is 32 raw random bytes. Mount the gateway TLS certificate/key as `/cfg/gateway.crt` and `/cfg/gateway.key`, and source CA as `/cfg/ca.pem`. Provide an explicit verified-email allow-list. Pin the source CA; never disable issuer, nonce, email-verification or TLS validation.

Envoy is the only public TLS listener. OAuth2 Proxy has no published port and trusts forwarding headers only from that exact Envoy IP. The backend joins a private network shared only with OAuth2 Proxy, with no published port or public ingress. Native Envoy removes caller-supplied Authorization, identity, groups and forwarding headers before setting authoritative HTTPS/peer headers. Native OAuth2 Proxy supplies verified user/email. No group authorization is configured. This client requests no group scope or mapping; the tested ID token has no groups claim. Native OAuth2 Proxy can forward groups if the issuer later adds them, so the backend must ignore that header and treat any group mapping as a separate reviewed profile. Do not authorize a user from a group header or expose the backend through a second ingress. Host/network administrators and the backend itself remain trusted.

Cookies use `__Host-asterius_gateway`, Secure, HttpOnly, Path `/`, no Domain, SameSite Lax, a 30-second expiry, and no automatic refresh. Login callback CSRF and a real cross-site browser POST are tested. Applications still enforce their own CSRF protection for mutations and authorization on verified identities. API paths `/api/*` return 401 for absent sessions; other application routes initiate login. No JWT bearer-token bypass or unauthenticated application route is enabled. Native health and OAuth login endpoints remain public. The cookie session is minimal, with unneeded OAuth tokens removed. Native OAuth2 Proxy forwards this gateway cookie to the trusted backend; the backend must protect it from logs, disclosure and reuse. Minimal cookie storage does not make that cookie non-sensitive.

OAuth access/ID tokens and incoming Authorization headers are not delegated to the application. This boundary authenticates a browser session; it does not make downstream requests DPoP-bound. Asterius source logout does not immediately invalidate the cached gateway cookie. Its expiry bounds retained access to 30 seconds; gateway logout clears that gateway session. Cookie key rotation invalidates all gateway cookies. This profile supplies no source-wide instantaneous revocation guarantee.

Install the locked browser dependencies with `npm ci --prefix e2e` and install Chromium using `cd e2e && npx playwright install chromium`. The runner also requires Docker, Python 3.11+, Node and OpenSSL. Run `scripts/gateway-acceptance.sh` with `ASTERIUS_BIN` pointing to a verified binary and `ASTERIUS_ACCEPTANCE_DB_CONTAINER` to a controlled disposable PostgreSQL fixture. It creates its own database, containers, networks and private files and cleans only those resources. Ports default to source 9454 and gateway 9455; environment overrides are available. Browser certificate bypass is confined to the self-signed fixture; the native proxy always validates the source CA. Production deployments provide separate trusted source CA and gateway certificate/key rather than the fixture's shared self-signed certificate.

The [2026-10-03 native evidence](evidence/gateway-2026-10-03.json) records 18 passing controls, runtime versions, pinned image digests, configuration hashes and the Asterius binary hash. It covers actual S256/nonce login, allowed and unassigned users, forged headers, login CSRF, cross-site POST, network isolation, source logout, tampering, expiry, reauthentication and gateway logout. The repeated login also verifies the exact registered callback CSP correction tracked by `ast-616n`. No token, credential or cookie value appears in the evidence.

Official option semantics: [OAuth2 Proxy configuration](https://oauth2-proxy.github.io/oauth2-proxy/configuration/overview/), [Envoy forwarding-header trust](https://www.envoyproxy.io/docs/envoy/latest/configuration/http/http_conn_man/headers).
